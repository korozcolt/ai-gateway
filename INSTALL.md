# Installation Guide

## Requirements

- PHP 8.3+, Laravel 13
- **PostgreSQL** (the migrations use sequences, `jsonb` and triggers)
- A queue worker if your queue is not `sync` (usage events are written through the queue)

## 1. Install

```bash
composer require korozcolt/ai-gateway
php artisan migrate
```

The package auto-registers its service provider and the `AiGateway` facade alias. Migrations are loaded from the package; publish them only if you need to edit them:

```bash
php artisan vendor:publish --tag=ai-gateway-migrations
php artisan vendor:publish --tag=ai-gateway-config
```

Tables created: `ai_providers` (connections, tokens as ciphertext) and `ai_usage_events` (append-only usage ledger).

## 2. Generate the credentials key

Provider tokens are encrypted before they are stored. The key that encrypts them is the **only** secret that lives outside the database (it cannot protect itself from inside it).

```bash
php artisan ai:generate-key
```

```env
AI_CREDENTIALS_KEY_ID=01j...        # system generated: copy it exactly, never type it by hand
AI_CREDENTIALS_KEY=base64:...       # AES-256-GCM key
```

Rules enforced at runtime (the call fails closed otherwise):

- the key must be a `base64:` value of the right length;
- it must differ from `APP_KEY`;
- it must differ from every key listed in `config('ai-gateway.credentials.distinct_from')` (add your other application keys, e.g. a chat encryption key);
- it never falls back to `APP_KEY`.

### Rotating the key

1. Run `php artisan ai:generate-key` again to get a new id/key pair.
2. Move the **previous** pair unchanged into `AI_CREDENTIALS_RETIRED_KEYS` as JSON: `{"<old id>":"base64:<old key>"}`.
3. Put the new pair in `AI_CREDENTIALS_KEY_ID` / `AI_CREDENTIALS_KEY`.

Old rows keep decrypting with the retired key; tokens you save from now on use the new key and record its id. Re-save (or `ai:providers:import --rotate-keys`) each connection to migrate it, then drop the retired key.

## 3. Add providers and tokens

Use any of:

1. **Seed file** (recommended): create `database/seeders/data/ai-providers.json` (git-ignore it!) and run `php artisan ai:providers:import [file] [--rotate-keys]`, or call `Korbytes\AiGateway\Database\Seeders\AiProvidersSeeder` from your `DatabaseSeeder`. The seeder always creates the offline `fake` connection too.
2. **Eloquent / your admin panel**:

   ```php
   use Korbytes\AiGateway\Models\AiProvider;

   $provider = AiProvider::create([
       'driver' => 'openai_compatible',
       'name' => 'NVIDIA Build',
       'base_url' => 'https://integrate.api.nvidia.com/v1',
       'supports_json_schema' => false,
       'is_active' => true,
       'models' => [['id' => 'vendor/model', 'input_price_usd_per_million' => 0.5, 'output_price_usd_per_million' => 1.5]],
   ]);
   $provider->replaceApiKey($token);   // encrypts and stores; the token is not mass-assignable
   ```

Typical `driver` / `base_url` pairs: `openai` / `https://api.openai.com/v1`, `anthropic` / `https://api.anthropic.com/v1`, `gemini` / `https://generativelanguage.googleapis.com/v1beta`, and `openai_compatible` with the provider's own URL (OpenRouter, NVIDIA Build, Azure v1, Mistral, Groq...).

Connection codes (`AIP-0001`, `AIP-0002`, ...) are generated by the database, immutable, and connections are never deleted (deactivate them: the usage ledger references them).

### Seed file reference

| Field | Required | Notes |
|---|---|---|
| `name`, `driver`, `base_url` | yes | `driver` must be in `config('ai-gateway.drivers')`; `base_url` must be `https://` |
| `api_key` | no | Encrypted on insert. An existing token is kept unless `--rotate-keys` |
| `supports_json_schema` | no | Default `false` |
| `is_active` | no | Default `false` |
| `models` | no | List of `{id, input_price_usd_per_million, output_price_usd_per_million, max_tokens_param?, temperature?}` |
| `request_options` | no | Extra body fields; may not set `model`, `messages`, `tools`, `response_format`, token limits, temperature or credentials |
| `budget_usd`, `verified_at`, `source_url` | no | Informational |

Import matches connections by `driver` + `name`, runs in one transaction, and on re-import only changes the fields the file states (settings an admin changed afterwards survive).

## 4. Database roles (optional hardening)

The package works with a single database user. If your application connects with a restricted role, grant it `SELECT/INSERT/UPDATE` on `ai_providers`, `INSERT/SELECT` on `ai_usage_events`, `USAGE` on the sequences `ai_provider_code_seq` and `ai_usage_event_code_seq`, and `EXECUTE` on `ai_usage_events_purge(timestamptz)` if you use retention purges.

## 5. Queue

The usage ledger is written by the queued job `RecordAiUsageEvent` (on the default queue unless `ai-gateway.usage.queue` is set), so a row survives a caller transaction that rolls back. The job ignores `after_commit` on purpose. With `QUEUE_CONNECTION=sync` it runs inline.

## 6. Verify

```bash
php artisan tinker
>>> Korbytes\AiGateway\Facades\AiGateway::available()
```

## Testing the package itself

```bash
composer install
composer test
```

PostgreSQL 16 is required. Create an empty database named `ai_gateway_test` and a local `phpunit.xml` (git-ignored) copied from `phpunit.xml.dist` that overrides the `DB_HOST`, `DB_PORT`, `DB_USERNAME` and `DB_PASSWORD` environment values with the ones of your PostgreSQL instance. Never commit credentials.
